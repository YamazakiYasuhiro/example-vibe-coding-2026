# 回答末尾の「まとめ」セクション付与

ユーザーへ最終回答を返すときは、本文のあとに必ず「まとめ」セクションを付ける。
途中経過の短い確認や、ツール実行のみの中間メッセージには付けなくてよい。
ユーザーが読む最終メッセージには必ず付ける。

## 必須ルール

1. 最終回答の末尾に、見出し `## まとめ` を置く
2. 「まとめ」は本文より前に置かない。回答本文の最後に置く
3. 内容は 2〜5 個の箇条書きで、次を優先して書く:
   - 何をしたか / 何が分かったか（結論）
   - 変更・成果物がある場合はその所在（パスや対象）
   - ユーザーに依頼・判断待ちがある場合はその要点
4. 本文の長文をそのまま繰り返さない。要点だけを短く言い切る
5. 「まとめ」見出しの表記は固定する（「サマリー」「Summary」「要約」などに変えない）

## 書式

```markdown
（回答本文）

## まとめ

- 要点1
- 要点2
- 要点3（あれば）
```

## 良い例 / 悪い例

**良い例**

```markdown
coding-rules のテスト命名規約を更新し、各エージェントへデプロイしました。

## まとめ

- テンプレート `prompts/manifest/code_content/policies/coding-rules.md` を更新した
- `tt prompt update --target all` で全ターゲットへ反映した
- レビュー後、必要ならコミットを依頼してほしい
```

**悪い例**

- 「まとめ」見出しが無い
- 本文の全文を「まとめ」に再掲している
- 「### Summary」など別名になっている
- 途中の進捗メッセージなのに毎回「まとめ」を付けて冗長になっている

## 適用タイミング

| 場面 | 「まとめ」 |
|------|------------|
| タスク完了の最終報告 | 必須 |
| ユーザーの判断・承認待ちで一旦返すとき | 必須 |
| 調査結果の説明 | 必須 |
| ツール実行中の短い中間報告 | 不要 |
| ユーザーの一文質問への短い確認だけ | 任意（最終回答なら付ける） |
